# Требования: пакет `letter` (шаг 1 roadmap)

Термины — из глоссария domain-model v1. Обозначения оснований: [Q-N] — ответ человека; [roadmap N] — docs/package-roadmap.md; [ДБ файл раздел] — docs/domain-research; П-N — правило domain-model.

## Цель
- Дать пользователям MuseX и будущим пакетам-потребителям (spelling, system, notation, interval и далее) единый словарь семи букв с циклическим порядком и буквенным расстоянием [roadmap, таблица №1].
- Чтобы потребители не считали по модулю 7 каждый сам и не дублировали перечень букв [Q-1; readiness.md].
- Результат: Go-пакет `letter` с публичным API, тестами, документацией и примерами; проверен ревью и QA; принят человеком [task-brief v2].

## Сценарии
Действующее лицо — программист, использующий библиотеку, или пакет-потребитель. Входы — допустимые буквы, если не сказано иное.

### Основные
- **С-1. Получить перечень букв.** Получить все буквы набора в каноническом порядке и их число. [Q-2, Q-5] Потребители: notation, system, search, modal.
- **С-2. Обойти круг от буквы.** Получить все буквы по кругу вверх, начиная с заданной. [Q-2; Д-1 модели] Потребитель: system (обход от граничной буквы).
- **С-3. Расстояние вверх.** Узнать число буквенных шагов вверх по кругу от X до Y (0…6). [Q-1 а] Потребители: interval, system.
- **С-4. Расстояние вниз.** Узнать число буквенных шагов вниз по кругу от X до Y (0…6). [Q-1 б] Потребитель: interval.
- **С-5. Сдвиг.** Получить букву, сдвинутую на любое целое число буквенных шагов (вверх — положительное, вниз — отрицательное), с переходом по кругу. [Q-1 в] Потребители: interval (перенос имени), system (буква регистровой позиции), соседняя буква.
- **С-6. Сравнить буквы.** Узнать, одна ли это буква, независимо от способа её получения. [ДБ 60 §1; ДБ 40 ИВ-1] Потребители: spelling, modal.

### Ошибочные
- **Е-1. Недопустимое значение буквы.** Если контракт допускает существование значения, не являющегося одной из семи букв (нулевое значение, внешние данные, Q-3), операции не выдают для него правдоподобный результат и не считают его буквой C или другой буквой [П-11; ДБ 40 ИВ-7]. Если контракт предусматривает создание буквы из внешнего значения [Q-3], недопустимое значение даёт различимую ошибку, а Must-вариант — панику [docs/rules/dev.md «Must»; ДБ 60 §6]. Способ — решение архитектора [Q-A1].

### Граничные
- **Г-1. Сдвиг на особые числа:** 0; ±7 и кратные 7; отрицательные; по модулю больше 7; крайние значения типа аргумента; переход B → C и C → B [П-5, П-6].
- **Г-2. Одинаковые и соседние буквы:** расстояние от буквы до неё же; соседние буквы через стык круга (B и C) [П-4].
- **Г-3. Полученный результат изменили.** Пользователь изменил полученный перечень или обход (если результат — изменяемая коллекция) — последующие результаты пакета и результаты других пользователей прежние [П-12; ДБ 60 §5].
- Пустых входов у операций нет: перечень и обход всегда содержат семь букв.

### Документация
- **С-7. Изучить пакет.** Программист узнаёт назначение пакета, понятия и операции из README, документации пакета и исполняемых примеров Go. [Q-7; README.md, комментарий-правило]

## Нефункциональные требования
- **НФ-1. Расширяемость наборов букв** [Q-5]. Публичное поведение пакета не закрепляет предположений, которые помешали бы в будущем добавить наборы букв любого количества без изменения смысла существующих операций для семи букв. Способ — решение архитектора [Q-A6]. Само расширение не реализуется.
- **НФ-2. Независимость.** Пакет не импортирует другие пакеты musex и не знает системы, нотации, октавы и альтерации [roadmap, таблица «Прямые импорты» №1; ДБ 20 раздел 4].
- **НФ-3. Неизменяемость и параллельность.** Буквы и набор неизменяемы; все операции безопасны при одновременном вызове из нескольких горутин; изменяемого общего состояния нет [ДБ 60 §1, §5].
- **НФ-4. Полнота операций.** Для допустимых букв операции С-1…С-6 всегда дают результат: без ошибок и паник. Паника — только в Must-вариантах [ДБ 60 §6; docs/rules/dev.md «Must»].
- **НФ-5. Качество.** Проверки проекта проходят: сборка, тесты с детектором гонок, golangci-lint по `.golangci.yml` [docs/rules/dev.md «Технологии»].
- **НФ-6. Документация.** Каждый экспортируемый идентификатор и сам пакет документированы на английском языке; README обновлён в разделах Features, Concept, Examples с пометкой unreleased; примеры Go исполняемые и их вывод проверяется [Q-7; README.md, комментарий-правило; docs/rules/main.md «Языки»]. Размещение и авторство — решение архитектора [Q-A5].

## Критерии приёмки
Примеры — фиксированные значения для тестов; «для всех» — полный перебор семи букв (49 пар) или указанных чисел.

| № | Сценарий | Критерий |
|---|---|---|
| К-1 | С-1 | Перечень = C D E F G A B именно в этом порядке; каждая буква ровно один раз; число букв = 7 и доступно через публичный API (отдельная операция или длина перечня — решение архитектора) |
| К-2 | С-2 | От C: C D E F G A B; от A: A B C D E F G; от B: B C D E F G A. Для каждой из 7 начальных букв: 7 элементов, все различны, i-й = сдвиг(начало, i) |
| К-3 | С-3 | C→E = 2; B→D = 2; E→F = 1; G→C = 3; B→C = 1; C→B = 6; C→C = 0. Для всех 49 пар: результат в 0…6 и равен (ord(Y) − ord(X)) mod 7 |
| К-4 | С-4 | C→E = 5; E→C = 2; D→B = 2; C→B = 1; C→C = 0. Для всех 49 пар: вниз(X, Y) = вверх(Y, X); при X ≠ Y вверх + вниз = 7; при X = Y оба 0 |
| К-5 | С-5 | C+0 = C; C+1 = D; B+1 = C; C+9 = E; G+4 = D; C+7 = C; C+70 = C; C−1 = B; C−7 = C; C−8 = B; E−2 = C. Для всех букв X и n из {−15…15}: сдвиг(X, n) = буква с местом (ord(X) + n) mod 7; сдвиг(сдвиг(X, n), −n) = X. Для всех 49 пар: сдвиг(X, вверх(X, Y)) = Y и сдвиг(X, −вниз(X, Y)) = Y |
| К-6 | С-6 | сдвиг(C, 9) равна E; сдвиг(B, 1) равна C; обход от A, элемент 2, равен C из перечня; все 7 букв попарно различны |
| К-7 | Е-1 | Для каждой публичной операции, принимающей букву, контракт определяет поведение при недопустимом значении (или показывает, что такое значение получить нельзя); ни одна операция не возвращает для него результат как для допустимой буквы; тесты проверяют это для каждой такой операции. Если есть создание из внешнего значения: недопустимое значение → различимая ошибка (проверяется `errors.Is` или иным способом из контракта), Must-вариант → паника |
| К-8 | Г-1 | Результат сдвига математически верен на крайних значениях типа аргумента, без переполнения: например, для 64-битного знакового целого C + (2^63 − 1) = C, C + (−2^63) = B; для выбранного архитектором типа — те же проверки на его минимуме и максимуме |
| К-9 | Г-2 | Покрыто К-3, К-4: расстояние до себя 0; B→C вверх = 1, C→B вниз = 1 |
| К-10 | Г-3 | После изменения полученного перечня (обхода) повторный вызов возвращает прежний результат (К-1, К-2). Неприменимо, если контракт возвращает неизменяемый результат — это указано в architecture |
| К-11 | НФ-1 | architecture описывает, как контракт допускает будущие наборы букв без изменения смысла операций для семи букв; code-reviewer подтверждает это на review-design |
| К-12 | НФ-2 | Пакет не импортирует пакеты musex (проверяется по списку импортов) |
| К-13 | НФ-3 | Параллельные вызовы всех операций под детектором гонок: гонок нет, результаты совпадают с К-1…К-6 |
| К-14 | НФ-4 | Для всех допустимых букв операции С-1…С-6 не возвращают ошибку и не паникуют (перебор К-3…К-5) |
| К-15 | НФ-5 | Сборка, `go test -race` и golangci-lint по `.golangci.yml` проходят без ошибок |
| К-16 | С-7, НФ-6 | Документация пакета и каждого экспортируемого идентификатора на английском; README: разделы Features, Concept, Examples описывают реализованное, помечено unreleased; исполняемые примеры Go есть как минимум для С-1…С-5, их вывод проверяется при запуске тестов; отметка пункта 1 в ROADMAP.md отсутствует до приёмки и ставится после неё |

## Допущения
- Д-1. Обход — только вверх по кругу; основание — пример в Q-2. Обход вниз — сдвигом на −1 (domain-model, Д-1).
- Д-2. Документация на английском языке: так написаны README.md и ROADMAP.md; комментарии в коде — американский английский [docs/rules/main.md «Языки»].
- Д-3. Диапазон аргумента сдвига ограничен только типом, выбранным архитектором; внутри него результат верен для любого значения (К-8) [Q-A6].
- Д-4. Порядковые места 0…6 используются в критериях как способ проверки; публичный ли это API — решение архитектора [Q-3].
