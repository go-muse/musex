## Неблокирующие замечания

### Н-10 (новое). Отчёты ревью во «Входах» architecture и implementation-plan
- **Место:**
  - architecture v5, шапка, «Входы»: `code-reviewer/review-design/review-report v1 — обратная связь, учтена` и `code-reviewer/review-tests/review-report v1 — обратная связь, учтена (Н-1)`;
  - implementation-plan v4, шапка, «Входы»: `code-reviewer/review-design/review-report v1`.
- **Суть.** artifacts/README: «Отчёты проверки — review-report и test-report — во „Входы“ не записываются: это обратная связь, а не основа работы. Новая версия отчёта не делает работу устаревшей». Если отчёт указан во «Входах», формальная сверка версий сочтёт документ устаревшим при каждой новой версии отчёта. Это уже возможно: review-design выпускает новые версии, review-tests будет выпускать свои. Какие отчёты учтены, уже записано в разделах «Учтённые замечания» документов, и этого достаточно. В плане это нарушение есть с версии 3; прошлые запуски review-design его тоже пропустили.
- **Влияние.** На содержание решения не влияет. Риск — лишние перепроверки входов.
- **Предложение.** При следующей версии документов убрать отчёты ревью из «Входов», сохранив разделы «Учтённые замечания». Отдельную версию ради этого выпускать не обязательно. Оркестратору — не считать новые версии review-report устаревшими входами этих документов.
- **Адресат:** software-architect; сведения — оркестратору.
