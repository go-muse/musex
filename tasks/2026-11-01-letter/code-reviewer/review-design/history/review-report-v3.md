## Проверка изменений v3 → v4
- **architecture v4.**
  - Добавлено положение «Платформы»: только 64-битный `int`, основание — О-7.
  - Из `Shift` убраны значения для 32-битного `int` (D, A) и упоминание GOARCH=386/arm.
  - Остались значения `C.Shift(math.MaxInt) == C` и `C.Shift(math.MinInt) == B`: верно, 2^63 − 1 ≡ 0 и −2^63 ≡ 6 по модулю 7.
  - Р-7 переформулирован согласованно. Другие разделы не затронуты.
- **implementation-plan v4.**
  - Из К-5 и К-8 убраны ветки `strconv.IntSize` и ожидаемые значения для 32 бит.
  - Выборка больших сдвигов осталась прежней. Кратные 7 у краёв `int` на 64 битах дают `MaxInt` и `MinInt + 1`, оба ≡ 0 по модулю 7.
  - Возврат `Shift(n).Shift(-n)` по-прежнему исключён только для `math.MinInt`.
  - Ссылки «architecture v2» в общих входах и в зависимостях plan-1 заменены на v4.
- **Остатки поддержки 32 бит.** Не найдены. Встречаются только записи о самом решении О-7 и строка 129 плана («architecture версии 3» в разделе об учтённых замечаниях v1). Эта строка — историческая ссылка на место закрытия Н-2. Это не вход, и ошибкой она не является.
- **Согласованность с требованиями.**
  - К-8 requirements v3 требует проверок для 64-битного знакового целого («C + (2^63 − 1) = C, C + (−2^63) = B») и для минимума и максимума выбранного типа. Выбран `int`, он 64-битный. Требование выполнено, пересмотр требований не нужен.
  - К-5 и Д-3 требований (диапазон ограничен только типом) не затронуты.
- **Влияние на цепочку.** Контракт API, НФ-1 / К-11, разделение авторов, порядок «тесты до реализации», plan-7 и проверки форматтеров не менялись. Продуктовый код по-прежнему не зависит от разрядности. Ограничение касается констант в тестах и примеров значений на краях `int`.
