# Постановка задачи: пакет `letter` (шаг 1 roadmap)

## Исходный запрос
Человек, 2026-11-01: «Изучи docs/package-roadmap.md и текущее состояние выполнения задач. Начни первую незавершённую задачу с готовыми зависимостями по настроенному процессу.»

## Цель
- Продукт: MuseX — библиотека музыкальной теории на Go (`github.com/go-muse/musex`), новая реализация на замену `muse` (docs/rules/main.md).
- Задача: пакет `letter` — первый пакет этапа 1 roadmap. Основание выбора: в репозитории нет Go-пакетов, в ROADMAP.md все пункты не отмечены; у `letter` нет прямых импортов.
- Для кого: пользователи библиотеки и последующие пакеты musex. Уточнение — у аналитика/человека.

## Контекст
- Место в roadmap: №1, ветка имён letter → alteration → spelling (решение 17). Обязанность по roadmap: «семь основных ступеней, их циклический порядок, буквенное расстояние»; ранее — `note.Name` в `muse`.
- Прямые потребители по таблице roadmap: `spelling` (3), `system` (9), `notation` (13), `interval` (18). Транзитивно — почти вся теория этапа 2 (интервалы, лады, ступени).
- Решения roadmap, касающиеся letter: 1 (тонкие пакеты), 2–4 (letter — основная ступень C D E F G A B), 16 (правило подпакетов для каталогов), 17 (порядок), 18 (позиции букв p(l) использует `system`; сам `letter` системы не знает — уточнить у аналитика/архитектора).
- Доменная база: `docs/domain-research` (README, 01-scope, 10-pitch-and-naming, 14-intervals, 20-relations, 30-operations, 40-invariants, 50-code-mapping, 60-design-implications, 70-open-questions и др.).
- Старый проект — только через MCP `gokg_muse`, не эталон требований.
- Правила разработки: Go 1.27.3, golangci-lint v2.15.0 (`.golangci.yml`), Must-обёртки, pointer receivers для доменных объектов, без vendor; тесты — Testify, t.Parallel(), табличные тесты; ветка `feat/1-<описание>`.

## Ожидаемый результат
- Форма: Go-пакет библиотеки `letter` с публичным API, тестами, проверенный ревью и QA.
- Основные функции текущего этапа: по roadmap — набор из семи букв, циклический порядок, буквенное расстояние. Точный объём (разбор/вывод строк? — по roadmap это `notation`) — уточнить.
- Признаки успеха: принятые требования и API; полный набор тестов принят до реализации; QA «принять»; приёмка человеком.

## Ограничения
- Вне объёма (по roadmap): альтерации, имена, октавы, нотация (разбор/вывод), позиции в системе.
- Коммиты и push — только пользователь; агенты могут создавать локальные ветки.
- `docs/books/` — только domain-researcher; `docs/setup/` — никому.

## Неизвестное
- Подтверждение человеком цели и границ (интервью аналитика, шаг 1).
- Нужны ли в `letter` строковые представления, нелатинские обозначения, проверка допустимости, итерация по кругу, направленное/ненаправленное расстояние.
- Требования ближайших потребителей (`spelling`, `system`, `interval`) к API `letter`.
