## Как проверить каждый шаг

### Подход к тестам (общий для plan-1…plan-3)
- **Внешний тестовый пакет** `letter_test`; только публичный API из architecture. Внутренний пакет `letter` в тестах не используется.
- **Testify**: `require` — для предусловий и проверок, после провала которых продолжать бессмысленно; `assert` — для независимых сравнений в таблицах. Ошибки — `require.ErrorIs(err, letter.ErrInvalid)`; текст ошибки не проверяется (не входит в контракт).
- **Табличные тесты** с именованными случаями (`name`) для однотипных проверок одной операции (docs/rules/dev-test.md); `t.Run` на случай.
- **Изоляция и параллельность**: `t.Parallel()` в каждом тесте верхнего уровня и в каждом подтесте; общих изменяемых данных между тестами нет; таблицы — локальные переменные теста; в Go 1.27 переменная цикла своя на итерацию — копировать не нужно. Время, случайность, файлы, сеть не нужны.
- **Оракул, независимый от реализации**: локальный в тестах литерал из семи констант в каноническом порядке `C D E F G A B`; порядковое место = индекс в литерале; ожидаемое вычисляется формулами требований (П-3, П-5) с математическим остатком, например `((x % 7) + 7) % 7`. Перечень пакета (`All`) как оракул для других операций не использовать.
- **Полный перебор**: 7 букв; 49 пар; сдвиги n ∈ [−15, 15] для каждой буквы; все 256 значений `uint8` для недопустимых значений.
- **Ожидаемые падения до реализации** (исключение «тесты до реализации» стека Go): `go test ./letter/...` и `go vet ./letter/...` не собираются с диагностикой об отсутствии не-тестовых Go-файлов в `github.com/go-muse/musex/letter` (или отсутствии символов API). Других пакетов в модуле нет. golangci-lint для пакета невыполним по той же причине — указать. Ошибки синтаксиса, неверные импорты, ошибки зависимостей — недопустимы: проверить форматтеры на своих файлах и что единственная причина сборочных ошибок — отсутствующий пакет или его символы.
- **Форматтеры `.golangci.yml` (gofmt и gci)** на своих файлах, без записи на месте в чужую область: `golangci-lint fmt --diff <свои файлы>` — пустой вывод (запись на месте `golangci-lint fmt <свои файлы>` допустима только по своим файлам). Порядок импортов — CONTRIBUTING.md: стандартная библиотека, `github.com/go-muse/musex/...`, сторонние (`github.com/stretchr/testify/...`) — тремя группами через пустую строку, по алфавиту внутри группы. Форматтерам компиляция не нужна; если до реализации команда всё же невыполнима — записать фактическую диагностику, проверить `gofmt -l` и порядок групп вручную.

### plan-1 — основное поведение
Проверяемые случаи (все из requirements v3):
- **К-1**: `All()` равен литералу оракула; длина = `letter.Count` = 7; все различны. `Count` — константа, пригодная как длина массива (объявление массива `[letter.Count]…` компилируется).
- **К-2**: `Cycle` от C, A, B — фиксированные последовательности; для каждой из 7 начальных: длина 7, все различны, элемент i = `start.Shift(i)` и = оракул[(ord(start) + i) mod 7]; `C.Cycle()` равен `All()`.
- **К-3**: таблица примеров (C→E 2, B→D 2, E→F 1, G→C 3, B→C 1, C→B 6, C→C 0); 49 пар: 0…6 и формула.
- **К-4**: таблица (C→E 5, E→C 2, D→B 2, C→B 1, C→C 0); 49 пар: `DistanceDown(a, b) == DistanceUp(b, a)`, сумма 7 при a ≠ b, оба 0 при a = b.
- **К-5**: таблица (C+0, C+1, B+1, C+9, G+4, C+7, C+70, C−1, C−7, C−8, E−2); 7 × n ∈ [−15, 15]: формула и возврат `Shift(n).Shift(-n)`; фиксированная выборка больших n для всех 7 букв: ±10^9, ±(10^9 + 3), ±2^31, ±(2^31 − 1), ±2^40, ±(7·2^40), ±(2^62 + 5), а также `math.MaxInt − math.MaxInt % 7` и `math.MinInt − math.MinInt % 7` (кратные 7 у краёв) — формула оракула и возврат (значения, не помещающиеся в 32-битный `int`, — только при `strconv.IntSize == 64`); fuzz-цель не требуется (Н-7); 49 пар: `a.Shift(a.DistanceUp(b)) == b`, `a.Shift(-a.DistanceDown(b)) == b`.
- **К-6**: `C.Shift(9)` равна `E`, `B.Shift(1)` равна `C`, `A.Cycle()[2]` равна `All()[0]` — каждая проверка и через `Equal`, и через `==`; 7 букв попарно различны (49 пар: `a.Equal(b)` истинно ровно при совпадении индексов оракула и совпадает с `a == b`; симметричность `a.Equal(b) == b.Equal(a)`); буквы, полученные разными путями, — один ключ `map`.
- **К-8**: `Shift(math.MaxInt)`, `Shift(math.MinInt)`, `Shift(math.MaxInt - k)`, `Shift(math.MinInt + k)` для малых k у всех 7 букв; ожидаемое — формулой без переполнения (остаток считать до сложения); дополнительно при `strconv.IntSize == 64`: `C + MaxInt = C`, `C + MinInt = B`; при 32: D и A. Возврат `Shift(n).Shift(-n)` не проверять для `n = math.MinInt` (в Go `-math.MinInt == math.MinInt`).
- **К-9**: входит в таблицы К-3, К-4.
- **К-14**: перебор К-3…К-5 под `require.NotPanics`; операции ошибок не возвращают (по сигнатурам).
- Q-3: `Ordinal` 0…6 по оракулу; `FromOrdinal(i)` для 0…6 — буква оракула и `nil`; `FromOrdinal(l.Ordinal()) == l`; `MustFromOrdinal(i)` для 0…6 без паники и равна букве оракула с местом i. `String` для 7 букв — `"C"…"B"`. Стабильные числа констант (architecture «Тип `Letter`»): `uint8(letter.C) == 1` … `uint8(letter.B) == 7` по оракулу.
- Проверка шага: change-summary перечисляет требования и случаи; `golangci-lint fmt --diff letter/letter_test.go` пусто; `go.mod` содержит `github.com/stretchr/testify v1.11.1`; `go.sum` заполнен; ожидаемая диагностика отсутствующего пакета записана.

### plan-3 — недопустимые значения, владение, конкурентность, импорты
- **К-7** (таблица «Поведение при недопустимом значении» в architecture): по всем 256 значениям `letter.Letter(v)` ровно 7 допустимы (`IsValid`), и это семь констант. Для каждого недопустимого v, включая нулевое `var l letter.Letter`: `IsValid` false; `Equal` false, когда недопустим получатель, аргумент или оба (с каждой из 7 букв и с самим собой: `v.Equal(v)` — false); `Ordinal` −1; `DistanceUp`/`DistanceDown` −1, когда недопустим получатель и когда недопустим аргумент (с каждой из 7 букв), и когда оба; `Shift(n)` для n ∈ {−8, −1, 0, 1, 7, math.MinInt, math.MaxInt} — результат недопустим и равен нулевому `Letter`; `Cycle()` — длина 0 (nil); `String()` = `fmt.Sprintf("Letter(%d)", v)` и не равна ни одному из "C"…"B"; `!=` каждой из семи констант. `FromOrdinal` для {−1, 7, 8, 100, math.MinInt, math.MaxInt}: `ErrorIs(ErrInvalid)`, возвращённая буква равна нулевому значению (`== letter.Letter(0)`, то есть `var zero letter.Letter`); `MustFromOrdinal` для тех же — паника, восстановленное значение — `error`, `errors.Is(…, ErrInvalid)` (через `recover` в помощнике теста; `assert.PanicsWithError` не подходит — он сравнивает текст ошибки, а текст не входит в контракт).
- **К-10**: изменить все элементы среза `All()` и среза `Cycle()` (для каждой начальной буквы), затем повторный вызов возвращает прежний результат; дополнительно `append` к полученному срезу не влияет на следующий вызов.
- **К-13**: N горутин (`sync.WaitGroup.Go`, N порядка `runtime.GOMAXPROCS(0) * 4`, без `time.Sleep`) одновременно вызывают все операции (включая `Equal`) для всех букв и пар, сверяют результаты с оракулом и меняют свои полученные срезы; результаты собираются через канал или срез по индексу горутины, проверка `assert` — после `wg.Wait()` в горутине теста (вызов `require` из рабочих горутин запрещён). Гонки ловит `go test -race`; тест обязан выполняться под `-race` (так в CI).
- **К-12**: тест со стандартным `go/build` (`build.ImportDir(".", 0)` из каталога пакета): список не-тестовых импортов пакета не содержит путей с префиксом `github.com/go-muse/musex` и путей сторонних модулей (только стандартная библиотека — признак: в первом элементе пути нет точки). Это автоматическая проверка списка импортов, а не чтение реализации автором тестов. Дублируется командой QA (ниже).
- Проверка шага: change-summary со связью «критерий → тест»; `golangci-lint fmt --diff` на файлах шага пусто; ожидаемая диагностика.
