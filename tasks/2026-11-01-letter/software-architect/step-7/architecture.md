### Сводка
```go
package letter // import "github.com/go-muse/musex/letter"

type Letter uint8

const (

    E
    F
    G
    A
    B

```
Тексты doc-комментариев пишет автор реализации на английском; смысл каждого — ниже. Других экспортируемых идентификаторов нет.

### Тип `Letter`
- Объявление: `type Letter uint8` — определённый тип, получатели и результаты по значению — исключение из правила docs/rules/dev.md «pointer receiver и возврат указателя» для пакета `letter`; основание — решение человека Q-SA1 (вариант «(а) uint8 + Equal»).
- **Допустимые значения** — ровно семь констант `C D E F G A B`. Любое другое значение типа, в том числе нулевое (`var l Letter`, `Letter(0)`) и полученное преобразованием числа (`Letter(42)`, `letter.B + 1`), — **недопустимое значение**: не буква (Е-1, П-11).
- **Нулевое значение** недопустимо и означает «буква не задана». Оно не равно `C` и не подменяется на `C` (ИВ-7; Q-A1). Все методы допустимы на нулевом значении и дают результаты для недопустимого значения (таблица ниже).
- **Числовые значения констант** C = 1, D = 2, E = 3, F = 4, G = 5, A = 6, B = 7 **стабильны** и входят в контракт как внутреннее представление: их выводят кодировщики на основе reflection (`encoding/json`, `encoding/json/v2`, `encoding/gob`, `fmt` с `%d`), поэтому они не меняются (Q-8 (а), Р-3). Это **не** порядковое место (C = 1, а `Ordinal` C = 0) и **не рекомендуемый** формат хранения: для хранения и обмена — `Ordinal`/`FromOrdinal` (с проверкой) или `String`. Базовый тип — `uint8`; допустимы ровно эти семь значений, 0 и 8…255 недопустимы. Преобразование `Letter(n)` проверки не делает, арифметика над буквами (`letter.C + 2`) не является сдвигом по кругу (`letter.B + 1` — недопустимое значение); для сдвига — `Shift`, для числа из данных — `FromOrdinal`. Doc-комментарий типа `Letter` говорит это явно.
- **Создание:** константы; `FromOrdinal`/`MustFromOrdinal`; результаты операций (`Shift`, `All`, `Cycle`). Фабрика для обычного использования не нужна.
- **Равенство** (П-9, О-6, К-6): метод `Equal` (раздел ниже) — основной способ, единый стиль с будущими типами musex; оператор `==` для допустимых букв даёт тот же результат: `letter.C.Shift(9) == letter.E` и `letter.C.Shift(9).Equal(letter.E)` — оба `true`. Тип сравним, пригоден ключом `map` и в `switch`. Недопустимое значение никогда не равно допустимой букве ни по `==`, ни по `Equal`; два недопустимых значения по `==` равны, только если совпадают их числовые значения (смысла не несёт), по `Equal` — никогда.
- **Копирование:** присваивание и передача по значению — полная копия одного байта; общих вложенных данных нет. Явного копирования не требуется.
- **Изменяемость:** ни один метод не меняет получатель, аргументы или данные пакета. Каждая операция возвращает новый результат (П-12, НФ-3, ДБ 60 §2 — стиль `l = l.Shift(1)`).
- **Указатель `*Letter`:** методы с получателем-значением доступны и у `*Letter` (набор методов Go); nil-указатель на получателя невозможен в API пакета — пакет указатели не принимает и не возвращает.
- **Конкурентность:** все функции и методы безопасны при одновременном вызове из любого числа горутин без синхронизации; у пакета нет изменяемого состояния (НФ-3, К-13).
- **Сериализация:** собственной нет. Пакет не реализует `encoding.TextMarshaler`, `json.Marshaler` и т.п. (Р-3); кодировщики на основе reflection выводят стабильное внутреннее число (пункт выше). Рекомендуемое хранение — `Ordinal` или `String`.

### Константа `Count`
- `const Count = 7` — нетипизированная константа: число букв **набора семи букв** (К-1, Q-A6). Пригодна для арифметики любого целого типа (`Count*w + h`, `floor(u/Count)` в system) и как длина массива (`[letter.Count]string` — таблицы notation).
- Равна `len(All())` и `len(l.Cycle())` для любой допустимой `l`.

### `func All() []Letter` — перечень (С-1, О-1)
- Возвращает семь букв в каноническом порядке `C D E F G A B` (К-1).
- **Владение:** каждый вызов возвращает новый срез длины и ёмкости `Count`; вызывающий владеет им, может менять и хранить. Изменение среза не влияет на последующие вызовы и на других пользователей (Г-3, К-10, П-12).
- Ошибок и паник нет.

### `func (l Letter) Cycle() []Letter` — обход круга (С-2, О-2)
- Для допустимой `l`: `Count` букв по кругу вверх, начиная с `l`; элемент с индексом i (с 0) равен `l.Shift(i)` (П-8, К-2). `letter.C.Cycle()` равен `All()`.
- Для недопустимой `l`: `nil` (длина 0).
- **Владение:** как у `All` — новый срез на каждый вызов, принадлежит вызывающему.
- Обхода вниз нет: `Shift(-i)` (Д-1 модели).

### `func (l Letter) DistanceUp(to Letter) int` — расстояние вверх (С-3, О-3)
- Для допустимых `l`, `to`: число буквенных шагов вверх по кругу от `l` до `to`, `(ord(to) − ord(l)) mod 7`, в диапазоне 0…6 (П-3, К-3). `l.DistanceUp(l) == 0`.
- Если `l` или `to` недопустимы: `-1`.
- Результат — число буквенных шагов, не ступеневая величина интервала (она = расстояние + 1, обязанность interval) и не `system.Step`.

### `func (l Letter) DistanceDown(to Letter) int` — расстояние вниз (С-4, О-4)
- Для допустимых: `(ord(l) − ord(to)) mod 7`, 0…6 (П-3, К-4). Свойства: `a.DistanceDown(b) == b.DistanceUp(a)`; при `a != b` `a.DistanceUp(b) + a.DistanceDown(b) == Count`; при `a == b` оба 0 (П-4).
- Если `l` или `to` недопустимы: `-1`.

### `func (l Letter) Shift(steps int) Letter` — сдвиг (С-5, О-5)
- Для допустимой `l`: буква с порядковым местом `(ord(l) + steps) mod 7`; `steps > 0` — вверх, `< 0` — вниз, любое значение `int` (П-5, Д-3 требований).
- **Без переполнения** на всём диапазоне `int`, включая `math.MinInt` и `math.MaxInt` (К-8). Ограничение на реализацию: сначала привести `steps` по модулю `Count`, затем складывать с местом; промежуточные значения не выходят за ±13.
  - `C.Shift(math.MaxInt) == C` (2^63 − 1 ≡ 0 mod 7), `C.Shift(math.MinInt) == B` (−2^63 ≡ 6) — `int` 64-битный (раздел «Контекст», О-7).
- Свойства (П-6, П-7): `l.Shift(0) == l`; `l.Shift(n + Count) == l.Shift(n)`; `l.Shift(n).Shift(-n) == l` (для `n != math.MinInt`: `-math.MinInt` переполняется в самом Go); `a.Shift(a.DistanceUp(b)) == b`; `a.Shift(-a.DistanceDown(b)) == b`.
- Для недопустимой `l`: нулевое значение `Letter` (недопустимое) при любом `steps`.
- Тип аргумента — `int` (Q-A4, Q-A6; решение КР-4).

### `func (l Letter) Ordinal() int` — порядковое место (Q-3)
- Для допустимой: 0…6 в каноническом порядке (C = 0 … B = 6); равно `letter.C.DistanceUp(l)`.
- Для недопустимой: `-1`.
- Пригодно как индекс таблиц: `symbols[l.Ordinal()]` при проверенной `l`.

### `func FromOrdinal(ordinal int) (Letter, error)` — буква из порядкового места (Q-3, Е-1)
- `0 ≤ ordinal < Count` → буква с этим местом и `nil`. `FromOrdinal(l.Ordinal()) == l` для каждой допустимой `l`.
- Иначе (отрицательные, `≥ Count`, крайние значения `int`) → нулевое значение `Letter` и ошибка, для которой `errors.Is(err, ErrInvalid) == true`. Текст ошибки содержит переданное значение, например `letter: invalid letter: ordinal 7 out of range [0, 6]`; текст не входит в контракт.
- Подстановки «ближайшей» буквы или взятия по модулю нет (ИВ-7). Для приведения по кругу — `letter.C.Shift(n)`.

### `func MustFromOrdinal(ordinal int) Letter`
- Обёртка над `FromOrdinal` (docs/rules/dev.md «Must»): при `nil`-ошибке возвращает букву; иначе `panic` со значением ошибки, которую вернул `FromOrdinal` (`recover()` даёт `error`, `errors.Is(…, ErrInvalid)`).
- Назначение — литералы и заведомо корректные значения в коде программиста (ДБ 60 §6).

### `var ErrInvalid`
- Sentinel-ошибка «значение не является буквой». Предполагаемый текст `"letter: invalid letter"` в контракт **не входит**, как и текст ошибок `FromOrdinal` и значения паники `MustFromOrdinal`: проверка — только `errors.Is`. Исполняемые примеры и тесты текст ошибок не печатают и не сравнивают. Возвращается (обёрнутой) только `FromOrdinal`; потребители (spelling и др.) могут оборачивать её при проверке своих входов.

### `func (l Letter) Equal(other Letter) bool` — равенство (С-6, О-6)
- `true` тогда и только тогда, когда `l` и `other` — допустимые буквы и это одна буква, независимо от способа получения (П-9): `letter.C.Shift(9).Equal(letter.E)`, `letter.B.Shift(1).Equal(letter.C)`.
- **Согласованность с `==`:** для допустимых `l` и `other` `l.Equal(other) == (l == other)`. Отличие только на недопустимых значениях: если `l` или `other` недопустимы, `Equal` возвращает `false`, в том числе для одинаковых недопустимых значений (`var z letter.Letter; z.Equal(z) == false`, хотя `z == z`). Так `Equal` не выдаёт для недопустимого значения результат «это та же буква» (К-7).
- Свойства на допустимых: рефлексивность, симметричность, транзитивность. Не меняет аргументы, безопасен конкурентно.
- Для ключей `map`, `switch` и `slices.Contains` используется сам тип (`==`); `Equal` удобен в цепочках и в обобщённом коде с методом равенства.

### `func (l Letter) IsValid() bool`
- `true` — ровно для семи констант; `false` — для нулевого и любого другого значения.

### `func (l Letter) String() string` — строковая форма (Q-4)
- Допустимые: `"C" "D" "E" "F" "G" "A" "B"` — фиксированная форма для fmt, логов, сообщений об ошибках и тестов. Реализует `fmt.Stringer`, поэтому `fmt.Println(letter.All())` печатает `[C D E F G A B]`.
- Недопустимые: `"Letter(<число>)"`, где число — десятичное значение `uint8(l)`: `Letter(0)`, `Letter(42)`. Никогда не совпадает с символом буквы.
- Это **не нотация**: не меняется настройками, не локализуется, обратного разбора нет. Разбор строк, «H», слоги, регистр — только `notation` [roadmap 11, 13]; notation не опирается на `String` и строит свои таблицы по `Ordinal`, `Count` или ключам `Letter`.

### Поведение при недопустимом значении (К-7)
| Операция | Недопустимый вход | Результат |
|---|---|---|
| `IsValid` | получатель | `false` |
| `Equal` | получатель или аргумент | `false` (в том числе для двух одинаковых недопустимых) |
| `Ordinal` | получатель | `-1` |
| `DistanceUp`, `DistanceDown` | получатель или аргумент `to` | `-1` |
| `Shift` | получатель | нулевое `Letter` (недопустимо) |
| `Cycle` | получатель | `nil` |
| `String` | получатель | `"Letter(<число>)"` |
| `==` | любой операнд | недопустимое ≠ любая из семи букв (два одинаковых недопустимых равны между собой — смысла не несёт, используйте `Equal` или `IsValid`) |
| `FromOrdinal` | число вне 0…6 | нулевое `Letter`, ошибка `ErrInvalid` |
| `MustFromOrdinal` | число вне 0…6 | паника с ошибкой `ErrInvalid` |
| `All`, `Count` | входов нет | — |
- Ни одна операция не паникует (кроме `MustFromOrdinal`) и не возвращает для недопустимого значения результат, возможный для допустимой буквы: −1 вне 0…6, нулевое `Letter` не буква, `nil` вне длины 7.
- Для допустимых букв операции С-1…С-6 всегда дают результат без ошибок и паник (НФ-4, К-14).

### Свойства, зависящие от числа букв (НФ-1 п. 2, К-11 б)
Документация пакета (`doc.go`) и doc-комментарии `Count`, `All`, `Cycle`, `DistanceUp`, `DistanceDown`, `Shift`, `Ordinal`, `FromOrdinal` называют диапазон 0…6, период 7 и семь элементов свойствами **набора семи букв** (seven-letter set), а не свойствами любой буквы любого набора. Пакет описывается как «the seven-letter set C D E F G A B»; тип `Letter` — «a letter of the seven-letter set».

### Примеры использования (публичный API)
Обычное использование:
```go
e := letter.C.Shift(9)                 // E
d := letter.B.DistanceUp(letter.D)     // 2
down := letter.C.DistanceDown(letter.E) // 5
for i, l := range letter.A.Cycle() {   // A B C D E F G; i = 0…6
    _ = l.Shift(-i) == letter.A        // true
}
var symbols [letter.Count]string       // table indexed by Ordinal
symbols[letter.G.Ordinal()] = "sol"
n := letter.MustFromOrdinal(2).Shift(3) // A: ordinal 2 is E, E shifted up 3 is A (Must wrapper in a chain)
seen := map[letter.Letter]bool{letter.C.Shift(7): true} // key C
letter.C.Shift(9).Equal(letter.E)      // true; same as letter.C.Shift(9) == letter.E
```
Изменение полученного результата:
```go
all := letter.All()
all[0] = letter.B          // changes only the caller's copy
fmt.Println(letter.All())  // [C D E F G A B]
```
Ошибки и граница:
```go
l, err := letter.FromOrdinal(7)
errors.Is(err, letter.ErrInvalid) // true; l is the zero Letter
l.IsValid()                       // false

var zero letter.Letter            // not C
zero.String()                     // "Letter(0)"
zero.DistanceUp(letter.C)         // -1
zero.Shift(1).IsValid()           // false
zero.Cycle() == nil               // true
zero.Equal(zero)                  // false: an invalid value is not a letter
zero.Equal(letter.C)              // false

letter.MustFromOrdinal(-1)        // panics with an error wrapping ErrInvalid
letter.C.Shift(math.MinInt)       // B on 64-bit int, no overflow
letter.Letter(3)                  // E (stable internal value 3), but unchecked and not an ordinal;
letter.Letter(9).IsValid()        // false; for numbers from data use FromOrdinal
```

## Владение данными
- Пакет `letter` владеет определением набора семи букв: составом, каноническим порядком, символами `String`. Это неизменяемые данные (константы и приватная таблица только для чтения); изменить их через API нельзя (П-12).
- Срезы, возвращённые `All` и `Cycle`, принадлежат вызывающему.
- Значения `Letter` копируются; общих данных между копиями нет.
- Позиции букв в системе, символы нотаций, альтерации, имена — данные других пакетов (system, notation, alteration, spelling); `letter` их не знает (НФ-2, П-10).

## Хранение данных меняется
Нет. Пакет не хранит данных, не работает с файлами и базами.

## Ответы на вопросы
### Q-3. Буква по порядковому номеру и номер буквы
- Да: `Ordinal() int` (0…6, −1 для недопустимого) и `FromOrdinal(int) (Letter, error)` с `ErrInvalid`, плюс `MustFromOrdinal` (dev.md «Must»). Тип номера — `int`.
- Почему: данные пользователей и вычисления потребителей приходят числами; notation и system индексируют таблицы по месту; Е-1 требует различимой ошибки, ИВ-7 — без подстановок (поэтому нет взятия по модулю в `FromOrdinal`).
- Числовое значение самой константы — не порядковое место (см. КР-1).

### Q-4. Строковая форма
- Да, только вывод: `String()` → `"C"…"B"`, для недопустимых `"Letter(n)"`. Разбора строк нет. Это не нотация (раздел `String`). Без `String` fmt печатал бы числа — сообщения и тесты потребителей были бы нечитаемы.

### Q-A1. Представление буквы и нулевое значение
- `type Letter uint8`, семь констант, нулевое значение недопустимо («буква не задана»), числовые значения констант стабильны, но не являются порядковым местом. Поведение всех операций для недопустимых значений определено (таблица выше). Альтернативы — КР-1.

### Q-A2. Правила dev.md для семизначной буквы
- **Must** применяется: единственная операция с ошибкой — `FromOrdinal`; к ней — обёртка `MustFromOrdinal` с паникой. Остальные операции ошибок не возвращают (НФ-4), поэтому Must-вариантов у них нет: правило dev.md требует, чтобы Must был обёрткой над методом с ошибкой, самостоятельных Must не бывает. Цепочки `letter.MustFromOrdinal(2).Shift(3).DistanceUp(letter.C)` работают.
- **Pointer receiver и возврат указателя:** для `letter` — исключение. Получатели и результаты по значению; основание — решение человека Q-SA1 (2026-11-01, вариант «(а) uint8 + Equal»; software-architect/questions.md). Вариант с указателями тоже выполнял бы требования (КР-2); выбор сделан по удобству и надёжности, а не из-за нарушения требований.
- Цель правила — цепочки вызовов (dev.md «Приёмники») — выполняется: метод с получателем-значением вызывается и на результате функции, и на `*Letter`: `letter.MustFromOrdinal(2).Shift(3).Equal(letter.A)` (место 2 — E, E + 3 = A).
- Для единого стиля с будущими доменными объектами добавлен метод `Equal` (решение человека Q-SA1).

### Q-A3. Правило подпакетов (решение 16)
- Не применяется: семь букв — значения самой сущности (как константы `time.Month`), а не каталог вариантов-определений (как темперации в `tuning/temperament`). Набор один и фиксирован [Q-5]. Подпакетов нет: вызов `letter.C` читается однозначно.
- Если в будущем появится каталог наборов букв — по решению 16 его место в подпакете `letter/<имя>`; это не меняет существующий API (см. НФ-1).

### Q-A4. Типы результатов и обход
- Расстояния и аргумент сдвига — `int` (КР-4). Путаница с величиной интервала и `system.Step` предотвращается тем, что у interval и system будут свои определённые типы: смешивание с ними потребует явного преобразования.
- Перечень и обход — новый `[]Letter` на каждый вызов (КР-6).
- Строковая форма согласована с notation: `String` — фиксированный отладочный вывод; notation задаёт свои символы и не зависит от `String` (раздел `String`).

### Q-A6. Контракт, не мешающий будущим наборам
- Смысл операций для N букв — из Д-3 модели (не выбирается здесь); форма контракта — раздел «НФ-1» ниже.
- Отдельная операция «число букв» нужна: константа `Count` (system считает `Count*w + h`, notation объявляет массивы `[Count]…`; `len(All())` дал бы лишнее выделение памяти и не константу).
- Аргумент сдвига — любой `int`, без ограничений диапазона и без переполнения (Г-1, К-8, Д-3 требований).

## НФ-1: будущие наборы букв (К-11)
Принцип: тип `Letter`, `Count`, `All`, `FromOrdinal`, `MustFromOrdinal` и все методы — это API **набора семи букв** и навсегда остаются им. Будущий набор с другим числом основных букв вводится **новым типом** (своим для набора или обобщённым), с операциями тех же имён и смысла. Существующий API при этом не меняется (Q-8 (а)).

### а) Результат операций для набора из N букв по Д-3 модели
| Операция (имя у будущего типа — то же) | Набор из N букв (Д-3) | При N = 7 (текущий набор) |
|---|---|---|
| `Count` | N | 7 (К-1) |
| `All` | N букв в договорном каноническом порядке набора | C D E F G A B (К-1) |
| `Cycle` от X | N элементов, i-й = сдвиг(X, i), i = 0…N−1 (П-8) | К-2 |
| `DistanceUp(X, Y)` | (ord(Y) − ord(X)) mod N, 0…N−1 (П-3) | 0…6, К-3 |
| `DistanceDown(X, Y)` | (ord(X) − ord(Y)) mod N, 0…N−1 (П-3) | 0…6, К-4 |
| `Shift(X, n)` | место (ord(X) + n) mod N, любое n, период N (П-5) | период 7, К-5 |
| `Equal`, `==` | равенство по содержимому (П-9); `Equal` — false для недопустимых | К-6 |
| `Ordinal` | 0…N−1 | 0…6 |
| `FromOrdinal` | допустимы 0…N−1, прочее — `ErrInvalid` | 0…6 |
| `IsValid` | принадлежность набору | семь констант |
| `String` | символы набора — Д-3 их не определяет (И-3) | "C"…"B" |
| недопустимые значения | та же таблица результатов (−1, нулевое значение, nil) | К-7 |
- Частный случай N = 1 (Д-3): расстояния 0, сдвиг — та же буква; формулы выше дают это без особых случаев.
- Операции между буквами разных наборов Д-3 не определяет; разные Go-типы делают такие вызовы ошибкой компиляции, а не неверным результатом.

### б) Документация
- Раздел «Свойства, зависящие от числа букв» выше; проверяет QA по doc-комментариям и `go doc`.

### в) Что добавить и что изменить при расширении
Добавить (вне текущего объёма):
1. Описание набора букв (число, канонический порядок, символы) — для каталога наборов по решению 16 подпакет `letter/<имя>` или новый пакет.
2. Тип буквы другого набора — отдельный Go-тип (для каждого набора или обобщённый по набору), чтобы буквы разных наборов нельзя было смешать.
3. Для него операции тех же имён и смысла: `IsValid`, `Equal`, `Ordinal`, `DistanceUp`, `DistanceDown`, `Shift`, `Cycle`, `String`; уровня набора — перечень, число букв, создание из места с ошибкой и Must-обёрткой.
4. По необходимости — обобщённое ограничение (интерфейс) с общим набором методов. Существующий `Letter` уже удовлетворяет ему по своим методам (`Shift` возвращает `Letter`, `DistanceUp` принимает `Letter`) без изменений; при необходимости метода уровня набора у буквы — он **добавляется** к `Letter`.
5. Документация и тесты нового набора; в doc-комментарий пакета — ссылка на другие наборы (дополнение текста, смысл операций не меняется).

Изменить: **ничего** из существующего публичного API — ни одной операции, её входов и результатов для семи букв. Программа для семи букв собирается и работает без правок, результаты К-1…К-10 прежние (К-11 г). Допустима только перестройка приватной реализации без изменения поведения.

### д) Нельзя создать иной набор
- Публичного конструктора набора, параметра «число букв» или изменяемой таблицы нет; `Count` — константа; допустимы ровно семь значений `Letter`. Проверяет QA по API (`go doc -all ./letter`).

## Ключевые решения и альтернативы
**КР-1. Представление: `type Letter uint8`, константы C…B, нулевое значение недопустимо, стабильные числа C = 1 … B = 7, не равные порядковому месту.**
- Альтернатива 1: `uint8`, C = 0 (как `note.Letter` в `muse`). Отклонена: нулевое значение — правдоподобная C (ИВ-7, П-11, Q-A1).
- Альтернатива 2: структура с неэкспортируемым полем, значения. Плюс: произвольное `Letter(42)` создать нельзя, остаётся только нулевое. Минусы: в Go нет констант-структур — буквы выдавались бы функциями `letter.C()` или экспортируемыми переменными (переприсваиваемыми во всей программе); нет проверки повторов `case` компилятором. Отклонена.
- Альтернатива 3: `*Letter` — КР-2.
- Цена выбранного: преобразование `Letter(n)` и арифметика возможны; закрыто определённым поведением для недопустимых значений и документацией (Р-1).

**КР-2. Получатели и результаты по значению, метод `Equal`** — исключение из правила dev.md о pointer receiver для `letter`; основание — решение человека Q-SA1 («(а) uint8 + Equal»).
- Альтернатива (б) по правилу dev.md: `type Letter struct{ ord uint8 }` с неэкспортируемым полем, функции `letter.C()`…`letter.B()` возвращают указатели на семь общих неизменяемых объектов пакета, методы с получателем-указателем, `Equal`, `MustFromOrdinal`.
  - Требования выполняет: равенство через `Equal` (П-9, С-6, О-6, К-6); неизменяемость и конкурентность — при условии контракта «через указатель не писать», как у `time.UTC` (П-12, НФ-3, К-10, Г-3); недопустимые значения — `nil` и пустая структура, обрабатываются всеми методами без паники (Е-1, К-7). Пересмотр требований не нужен.
  - Цепочки: `letter.C().Shift(9).Equal(letter.E())`; операции без выделения памяти (общие объекты), `All`/`Cycle` — один срез из 7 указателей.
  - Цена: `==` для указателей компилируется, но вне контракта (верен для объектов пакета, неверен для копии пользователя); ключи `map` и `switch` — через `Ordinal()` или `*l`; два вида недопустимых значений; защита от изменения — контракт, а не компилятор; поле-указатель в будущих типах может быть nil.
  - Довод за (б) — единый стиль с будущими доменными объектами-указателями. Человек выбрал (а) с `Equal`: тот же единый способ сравнения без цены (б).

**КР-3. Недопустимые значения дают определённые «не-буквенные» результаты** (−1, нулевое `Letter`, `nil`, `"Letter(n)"`), без ошибок и паник.
- Альтернатива 1: ошибка в каждой операции (`Shift(n) (Letter, error)` и Must-обёртки ко всем). Отклонена: для допустимых букв ошибка невозможна (НФ-4), цепочки и вызовы потребителей (interval, system) загромождаются ради значения, которое допустимым кодом не возникает.
- Альтернатива 2: паника. Запрещена вне Must (НФ-4, ДБ 60 §6).
- −1 как «нет результата» — идиома Go (`strings.Index`, `slices.Index`).

**КР-4. Тип расстояний и аргумента сдвига — `int`.**
- Альтернатива 1: отдельный тип `Steps`. Отклонена: лишние преобразования у всех потребителей; защиту от смешения с величиной интервала и `Step` дают типы interval и system.
- Альтернатива 2: `int64`. Отклонена: `int` — обычный тип счётчиков Go (`for i := range n`, индексы); корректность на всём диапазоне гарантирована (К-8).

**КР-5. `Count` — нетипизированная константа.**
- Альтернативы: только `len(All())` (не константа, выделение памяти); функция `Count()` (нельзя как длину массива). Отклонены.

**КР-6. `All` и `Cycle` возвращают новый `[]Letter`.**
- Альтернатива 1: общий пакетный срез — изменение одним пользователем видно всем (П-12). Отклонена.
- Альтернатива 2: массив `[Count]Letter` — без выделения памяти, но неудобен для `slices` и менее привычен. Отклонена; при доказанной профилем нужде возможно добавить (не менять) операцию.
- Альтернатива 3: итератор `iter.Seq[Letter]` — без индекса и длины; потребителям нужен индекс (П-8). Отклонена; может быть добавлен позже.

**КР-7. Числовой API — `Ordinal`/`FromOrdinal`/`MustFromOrdinal`** (Q-3).
- Альтернатива: без числового API (перебор `All`). Отклонена: notation и system индексируют таблицы; пользовательские данные приходят числами.

**КР-8. `String` без разбора** (Q-4). Альтернативы: без `String` (нечитаемый вывод); `Parse` в `letter` (вторая нотация, дублирует notation, roadmap 11). Отклонены.

**КР-9. Один пакет без подпакетов** (Q-A3, решение 1 «тонкие пакеты» соблюдено: одна обязанность).

**КР-10. Будущие наборы — новые типы, а не обобщение `Letter` сейчас** (НФ-1). Альтернатива: ввести сейчас абстракцию набора и хранить набор в букве. Отклонена: переусложнение для одного набора, расширение вне объёма [Q-5]; документация называла бы `Letter` буквой «любого набора» вопреки НФ-1 п. 2.

**КР-11. Зависимости:** продуктовый код — только стандартная библиотека; тесты — Testify (additions/team-additions.md), версия — в implementation-plan.

## Риски
- **Р-1. Числовые преобразования.** `letter.Letter(i)` вместо `FromOrdinal(i)` (сдвиг на 1: `Letter(0)` недопустима, `Letter(1)` = C) или `letter.B + 1` дают недопустимое или неожиданное значение. Снижение: doc-комментарий типа, `IsValid`, определённое поведение для недопустимых, примеры `FromOrdinal`. Линтером не ловится.
- **Р-2. −1 в арифметике потребителя.** Потребитель, не проверивший входы, получит −1 и, например, «размер» 0. Снижение: потребители проверяют буквы своих входов (`IsValid`) — правило для их проектирования; doc-комментарии.
- **Р-3. Сериализация.** `encoding/json` сейчас кодирует `Letter` числом (внутреннее значение). Добавление позже `MarshalText`/`MarshalJSON` изменило бы вывод существующих программ — нарушение Q-8 (а). Решение: у `Letter` нет и не будет методов сериализации без отдельного решения человека; рекомендуемые форматы хранения — `Ordinal`, `String` или notation. Числовые значения констант изменили бы такой вывод, поэтому они закреплены в контракте (раздел «Тип `Letter`»).
- **Р-4. Добавление методов к `Letter`** при расширении — совместимое по правилам Go изменение; теоретически ломает только код со встраиванием двух типов с одноимённым методом. Приемлемо.
- **Р-5. Два способа сравнения** (`==` и `Equal`) расходятся только на недопустимых значениях (раздел `Equal`). Снижение: doc-комментарий `Equal`; тесты К-7 проверяют оба.
- **Р-6. Слабейшая часть Д-3 — замыкание круга при N ≠ 7** (review-report анализа, Н-7). На семь букв не влияет; если будущий набор окажется не круговым, он всё равно вводится новым типом — существующий API не затрагивается.
- **Р-7. Только 64-битные платформы** (О-7): сборка под 32-битную платформу не поддерживается и не проверяется (CI — amd64); контракт `Shift` на крайних значениях и тестовые константы больше 2^31 рассчитаны на 64-битный `int`.
- **Р-8. `ErrInvalid` — пакетная переменная** (идиома Go, как `io.EOF`); её переприсваивание пользователем — нарушение его собственного кода, не пакета. Альтернатива — константа строкового типа ошибки — непривычна; отклонена.
- **Нагрузка и объёмы.** Все операции O(1); `All`/`Cycle` — одно выделение 7 байт на вызов, остальные без выделений (гипотеза без измерений; скилл golang-performance: бенчмарки не требуются, пока нет профиля потребителя). При росте нагрузки в system/search возможно **добавить** операцию без выделений (массив или итератор) — существующие не меняются. Конкурентных конструкций нет; совместное использование безопасно по построению (golang-concurrency: изменяемого общего состояния нет, горутин нет).
